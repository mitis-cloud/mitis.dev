# mitis.dev

The mitis website: a cloud consulting studio (cost reduction, Kubernetes
platforms, release automation). Astro 7 + Tailwind 4, static output, almost no
JavaScript.

## Structure

The home page answers, in order: what mitis does and for whom, the proof, the
three services, one result, how an engagement goes, why mitis, who we are.
Detail pages: `/servizi` (overview and how you buy), `/finops`, `/kubernetes`,
`/devops` (one per service), `/risultati`, `/metodo`, `/chi-siamo`,
`/open-source`, `/contatti`, `/faq`, plus `/privacy`, `/cookie` and a 404.
Sitemap generated by `@astrojs/sitemap`.

The site is bilingual: Italian at the root, English under `/en/` (translated
slugs: `/en/services`, `/en/results`, `/en/method`, `/en/about`,
`/en/contact`). Each page is one component in `src/pagine/` that holds its copy
as an `{ it, en }` object selected from the pathname; the files in `src/pages/`
only map routes to them. The three service pages share
`src/components/Servizio.astro`. The route map and helpers are in
`src/i18n.ts`, the FAQ in `src/faq-dati.ts` (entries are referenced by `id`).
Every page emits reciprocal `hreflang` links, one `h1`, and a JSON-LD graph
(organization, page, breadcrumb, plus `Service`, `FAQPage`, `AboutPage` or
`ContactPage` where they apply) from `src/layouts/Base.astro`.

## Writing rules

The reader is a CTO or founder who may not know Kubernetes. Every sentence on
the home page has to make sense to them: say what is done and what they get,
in plain words. Technical vocabulary belongs in the sections labelled as
technical detail on the service pages, and on `/open-source`.

## Commands

| command           | effect                                       |
| ----------------- | -------------------------------------------- |
| `npm install`     | dependencies                                 |
| `npm run dev`     | dev server on `localhost:4321`               |
| `npm run build`   | static build into `dist/`                    |
| `npm run preview` | serve `dist/` locally                        |
| `npm run og`      | regenerate `public/og.png` and `public/og-en.png` (requires playwright; set `OG_CHROMIUM` to point at an explicit chromium binary) |

## Data that may change

Contact details, the people of the studio, the case figures and the Understudy
results table live in **`src/dati.ts`**; the open source catalogue lives in
`src/open-source-dati.ts`. Change them there and rebuild.

- `persone` is empty: the about page then presents the studio without personal
  cards. Add entries (name, role, photo, link) and a people section appears.
- `contatti.prenotazione` takes a calendar link; when empty, the "book a call"
  buttons on the contact page fall back to a `mailto:`.
- Several pages state that the analysis takes two weeks. If that changes,
  search for it and align every occurrence.

## Deploy

Push to `main` → `.github/workflows/deploy.yml` builds and publishes to GitHub
Pages (`public/CNAME` points at `mitis.dev`). One-time setup on the GitHub
repo: Settings → Pages → Source: GitHub Actions, plus the `mitis.dev` DNS
(A/CNAME records towards GitHub Pages).

## Design system

One look, no theme switch. Tokens are in `src/styles/global.css`: a light
reading surface (`fondo`, `superficie`, `inchiostro`, `tenue`, `sottile`,
`filo`), a deep lake blue `accento` for links and marks, an orange `azione`
reserved for the call to action, and `notte` for dark bands. The `.buio` class
redefines the same tokens, so any component placed inside a dark band adapts
without its own dark styles.

Type: Newsreader (display, weight 450) for headings and large figures, Geist
for text, Geist Mono for code. All self-hosted in `public/fonts/` (OFL).

Photography shows built things: server hardware on the home page, steel
structures, bridge cables and a working desk elsewhere. Every photo is
converted to the same cool monochrome so the orange call to action is the only
colour on a dark band. The photographs are public domain; sources and authors
are in `public/img/CREDITI.md`. Page headers (`Testata.astro`) and the closing
call to action (`Cta.astro`) sit on photographs; the navigation is laid over
them. Keep any replacement in the same family: real hardware or structures, no
landscapes and no stock people.

Figures are HTML and CSS in `src/components/figure/`: the before/after spend
bars, the layers of the platform, the path of a change, the Understudy results
table and the one-file-per-service example. The only motion is bars growing
once when a figure scrolls into view.

The numbers on the site (the −70% case and its conditions, the Understudy
results) are the only quantitative claims allowed and must stay identical to
their sources. The Understudy figures come from the
[Understudy](https://github.com/mitis-cloud/understudy) README and must not be
rounded. The service example in `UnFile.astro` must keep rendering exactly five
objects (`helm template api charts/service -f <the excerpt>`).
